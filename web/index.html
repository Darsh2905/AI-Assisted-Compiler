Implementation status · 16 September 2026

ProveIt-C

A compiler for a small C-like language in which an AI proposes and a deterministic verifier decides. Every rewrite is an untrusted proposal until an SMT solver proves it equivalent over all inputs — and because operands and constants are symbolic, one proof covers every instance of the pattern, so the model never runs at build time.

Finding 1

Testing is budget-bound. Proving is not.

rulelib/stealth.rules holds rewrites that are wrong on a vanishing fraction of their input space. Each was run under eight tester configurations and against the solver.

Two things a bigger test budget will not fix

Uniform random sampling does not improve with budget. A thousandfold increase — 100 to 100,000 trials — catches nothing extra, because the rules it misses are wrong on roughly one input in 232. Boundary seeding recovers three of them and then also plateaus.

The fourth survives everything. A rewrite that is the identity for every constant except 0x5A5A5A5A escaped all eight configurations across 7.8 million trials. Boundary seeding covers the values someone thought to enumerate; it is a heuristic, not a method. The solver returns its counterexample in 13 ms.

Finding 2

Values are not the whole of meaning

The rule that is correct on every input and still unsound

shl_mask_trap_erasure masks a shift amount to five bits, exactly as the hardware does. In MiniC a shift of 32 or more traps, and a trap is observable. The rewrite agrees with the original on every input that produces a value, and is refuted only because it deletes a trap. A checker comparing values alone would pass it; this one reports refuted with the counterexample y = 32.

That is why the obligation discharged is trap-preserving equivalence: both sides must trap on the same inputs, and agree on values everywhere else.

Finding 3

Proven is not the same as profitable

A correct rule that made every program worse

The first run of the rule applier grew the benchmark suite by about 60%. The culprit was add_split_or_and — x + y == (x|y) + (x&y) — which is perfectly correct and turns one instruction into three. It fired 375 times.

A proof says a rewrite preserves meaning. It says nothing about whether the rewrite is an improvement, and the two decisions need separate machinery. The applier now consults a static cost model and fires a rule only when it strictly reduces cost: 12 of 20 proven rules qualify, and the other eight are kept in the library, marked, and never applied.

The reduction is small, and the reason is worth stating plainly: only 2 of the 12 applicable rules ever match six programs. That is a fact about the corpus, not about the method, and it is the strongest argument for the corpus work that comes next. Recompiling any program against the same library reproduces byte-identical IR.

Finding 4

Where the checker stops answering

Two rules in rulelib/hard.rules multiply symbolic 32-bit values on both sides with no shared structure — two full 32×32 multiplier circuits after bit-blasting. Z3 returns unknown on one run and sat on the next for the same query. They are quarantined, and only the safety half is asserted: an unsettled query must never be reported as proven. A timeout costs coverage, never soundness.

This is the same wall the recent literature reports. Kwon et al. (CGO '26) find ~20% of TSVC loops unverifiable by Alive2 even after verification-friendly rewriting; Fang et al. (CGO '26) exclude solver timeouts from their training set outright.

Honesty

What these numbers do not show

  • There is no LLM anywhere in this code. The project's headline question — how often is a test-passing rewrite actually wrong? — is not answered. What the detection matrix shows is that the apparatus would catch such rewrites, using rules we wrote specifically to be hard to catch.
  • MiniC is not C. Undefined behaviour was defined away so that equivalence would be decidable. That is the trade this design makes, and it means no result here is a result about C.
  • The IR is not in SSA form. phi exists in the representation and the round-trip tests, but nothing generates it.
  • The cost model is ordinal placeholders, not measured latencies. No performance claim is made and none should be read in.
  • Matching is syntactic and block-local. No reassociation, no canonicalisation. Reported match rates are a floor, not a ceiling.
  • Preconditions constrain constants only, so a rule needing a fact about a value — x % 2k == x & (2k−1) for non-negative x — cannot currently be expressed.
Reproducing

Run it

pip install -r requirements.txt

python3 -m pytest -q             # 184 assertions, every one with a threshold
python3 -m experiments.run_all   # regenerate every number on this page (~18 s)
./run_all.sh                     # both, non-zero exit on any regression

./provitc.py ir bench/bitmix.mc -O   # compile and optimise
./provitc.py library                 # what the verifier has admitted
./provitc.py verify                  # re-check every rule's declared verdict

A passing test here asserts a numeric threshold or an exact verdict. “The script ran without crashing” is the failure mode this project exists to argue against, so it is not allowed to count as a pass.
